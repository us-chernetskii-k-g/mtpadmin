# MTPADMIN — свой Telegram Proxy с веб-админкой

**MTPADMIN помогает поднять собственный Telegram Proxy на VPS и дальше управлять им через веб-панель.**

Текущая версия: **0.12.5**  
Статус: **Public Beta** — обновление существующей production-установки уже проверено вживую; сейчас особенно нужны отзывы о чистой установке на разных VPS и дистрибутивах Debian/Ubuntu.

После установки доступны два способа подключения к Telegram: обычный MTProto Proxy через **TeleMT** и **Telegram WEB Proxy** через HTTPS. В панели есть готовые ссылки и QR-коды, активные клиенты, локальная статистика и география, источники, Scanner Guard, диагностика и Центр обновлений.

> Установили один раз — дальше почти всё можно делать через веб-панель без постоянной работы в SSH.

### Обычный MTProto Proxy

Работает через **TeleMT**. Порт задаётся при установке; типичный вариант — `8443/tcp`.

### Telegram WEB Proxy

Работает через HTTPS на `443/tcp`:

```text
Telegram
   │
   │ HTTPS :443
   ▼
webproxy.example.com
   │
   ▼
Caddy
   │
   ▼
tproxy-server
   │
   ▼
localhost:2398
   │
   ▼
TelegramMessenger/MTProxy
   │
   ▼
Telegram
```

Служебный MTProxy backend не предназначен для прямого доступа из интернета. MTPADMIN создаёт отдельную nftables-таблицу, которая закрывает внешние подключения к служебным портам `2398` и `8888`, не переписывая пользовательские правила SSH или весь firewall целиком.

# Рекомендуемая схема доменов

Проще всего использовать три имени:

```text
proxy.example.com       — обычный MTProto Proxy
mtpadmin.example.com    — веб-админка
webproxy.example.com    — Telegram WEB Proxy
```

Обычный MTProto и один из HTTPS-сервисов могут использовать одинаковое доменное имя, если работают на разных портах. Например:

```text
proxy.example.com:8443  — обычный MTProto
proxy.example.com:443   — WEB Proxy
```

А вот домен веб-админки и домен WEB Proxy должны быть разными: оба используют HTTPS на `443`.

# Веб-панель

В актуальной 0.12.5 панель рассчитана и на компьютер, и на телефон. На десктопе используется боковая навигация, на мобильном — компактная нижняя. Технические детали вынесены в раздел **«Для специалистов»**.

Основные разделы:

- **Обзор** — здоровье системы, подключения, активные IP, статистика и обновления;
- **Статистика** — соединения, трафик, история, пики нагрузки;
- **Клиенты / Активные** — MTProto и WEB-клиенты в одном интерфейсе;
- **География** — страна, город, ASN и сеть;
- **Источники** — отдельные источники для сайта, друзей, рекламы и других задач;
- **Ссылки** — готовые ссылки и QR-коды;
- **Защита** — Scanner Guard, белый список и ручные блокировки;
- **Операции** — обновления, проверки и восстановление компонентов;
- **Настройки** — параметры панели и сервиса.

Автоматическая блокировка Scanner Guard **по умолчанию выключена**.

# Статистика и приватность

MTPADMIN показывает:

- текущие соединения;
- активные IP;
- трафик;
- статистику по источникам;
- историю клиентов;
- страны и города;
- ASN и сети;
- пики нагрузки.

Определение страны, города и сети выполняется **локально на сервере** по локальной базе. Список клиентских IP не нужно отправлять внешнему геосервису.

Служебная telemetry WEB Proxy также доступна только локально на сервере.

# Центр обновлений

В разделе **«Операции» → «Обновления»** отдельно показываются:

- MTPADMIN;
- TeleMT;
- Telegram WEB Proxy.

Обновление запускается отдельной systemd-задачей и продолжает выполняться, даже если закрыть вкладку браузера. Одновременно запускается только одна операция обновления.

Для WEB Proxy в 0.12.5 используются дополнительные меры защиты:

- новый `tproxy-server` сначала скачивается, тестируется и собирается без остановки рабочего relay;
- persistent token signing key создаётся один раз и сохраняется между обновлениями;
- при первой миграции включается совместимый drain старых relay-токенов;
- бинарники заменяются атомарно, без перезаписи работающего executable;
- telemetry проверяется после переключения;
- существующая публичная WEB-ссылка сохраняется;
- после успешного обновления состояние Центра обновлений синхронизируется автоматически.

# Диагностика

Главная команда:

```bash
mtpadmin doctor
```

Она проверяет TeleMT, статистику, DNS, служебные API, Scanner Guard, WEB Proxy, Caddy, память, swap, диск и другие важные части установки.

Для отчёта о проблеме полезно приложить вывод:

```bash
/usr/local/bin/mtpadmin doctor
systemctl --failed --no-pager
```

Не публикуйте содержимое `/etc/mtpadmin/state.env`, `config.toml`, `token.key`, пароли и секреты прокси.

# Требования

Clean installer 0.12.5 рассчитан на:

- **Debian или Ubuntu** с `apt`;
- `systemd`;
- `x86_64/amd64` или `aarch64/arm64`;
- публичный IPv4;
- root или `sudo`;
- обычную интерактивную SSH/консольную сессию;
- минимум **1 ГиБ свободного места** на файловой системе `/var/tmp`;
- доменные имена, заранее направленные DNS-записями на сервер.

Для HTTPS сервер должен быть доступен по `80/tcp` и `443/tcp`. Дополнительно должен быть открыт выбранный порт обычного MTProto Proxy, например `8443/tcp`.

Установщик до начала основных изменений проверяет ОС/архитектуру, корректность доменов и IPv4, свободное место и DNS. Основные shell-payload'ы сначала скачиваются во временные файлы, проходят `bash -n`, и только после подтверждения пользователя начинается изменение системы.

# Установка

## Рекомендуемый вариант

Сначала скачать bootstrap, проверить синтаксис и запустить его отдельно:

```bash
curl -fL \
  --connect-timeout 15 \
  --max-time 240 \
  --retry 5 \
  --retry-delay 2 \
  --retry-all-errors \
  https://raw.githubusercontent.com/us-chernetskii-k-g/mtpadmin/main/install.sh \
  -o /tmp/mtpadmin-install.sh

bash -n /tmp/mtpadmin-install.sh
sudo bash /tmp/mtpadmin-install.sh
rm -f /tmp/mtpadmin-install.sh
```

При старте с `main` установщик сначала фиксирует текущий `main` в конкретный Git commit и дальше загружает связанные payload'ы уже из этой ревизии. Это защищает установку от ситуации, когда `main` изменился прямо посреди процесса.

### Быстрая установка одной командой

Поддерживается и отдельно проверяется CI:

```bash
curl -fsSL https://raw.githubusercontent.com/us-chernetskii-k-g/mtpadmin/main/install.sh | sudo bash
```

Мастер спросит:

- домен обычного MTProto Proxy;
- публичный/NAT IPv4;
- порт MTProto Proxy;
- имя первого источника;
- FakeTLS-домен;
- существующий raw secret или разрешение создать новый;
- рекламную метку `@MTProxyBot`, если она нужна;
- рекламируемый Telegram-канал, если нужен;
- сроки хранения полной и обезличенной истории;
- домен, логин и пароль веб-админки;
- домен Telegram WEB Proxy.

Пароль и секреты не выводятся открытым текстом в итоговой сводке.

Если DNS не указывает на выбранный публичный IP, установщик показывает предупреждение и требует отдельного подтверждения.

# После установки

Откройте:

```text
https://mtpadmin.example.com/
```

Затем:

1. проверьте **«Обзор»**;
2. откройте **«Ссылки»** и подключите Telegram;
3. проверьте **«Активные»**;
4. при необходимости создайте дополнительные источники;
5. выполните `mtpadmin doctor`;
6. дальнейшие обновления ставьте через **«Операции» → «Обновления»**.

# Обновление из консоли

Основной путь — через веб-панель. Если панель недоступна, updater можно запустить вручную:

```bash
curl -fL \
  --connect-timeout 15 \
  --max-time 240 \
  --retry 5 \
  --retry-delay 2 \
  --retry-all-errors \
  https://raw.githubusercontent.com/us-chernetskii-k-g/mtpadmin/main/update.sh \
  -o /tmp/mtpadmin-update.sh

bash -n /tmp/mtpadmin-update.sh
sudo bash /tmp/mtpadmin-update.sh
```

Перед важными изменениями создаются резервные копии, а после обновления выполняются health-check'и. WEB Proxy дополнительно проверяет сохранение существующей публичной конфигурации.

# Частые вопросы

### Можно ли обновляться без SSH?

Да. Основной способ — **«Операции» → «Обновления»**.

### Что будет, если закрыть вкладку во время обновления?

Операция продолжится на сервере. Результат можно посмотреть после повторного открытия страницы.

### Сломается ли уже розданная WEB-ссылка после обновления?

Штатное обновление не должно менять публичный домен и секрет WEB Proxy. В 0.12.5 это отдельно проверяется updater'ом.

### Внутренний MTProxy для WEB Proxy доступен из интернета?

Нет. Backend работает на служебных портах, а MTPADMIN устанавливает отдельное правило, закрывающее внешние подключения к `2398/8888`. Пользователь подключается к WEB Proxy через HTTPS `443`.

### MTPADMIN — это VPN?

Нет. MTPADMIN предназначен именно для Telegram Proxy и не заменяет VPN для всего трафика устройства.

### Обязательно ли получать рекламную метку у `@MTProxyBot`?

Нет. Это необязательный параметр.
